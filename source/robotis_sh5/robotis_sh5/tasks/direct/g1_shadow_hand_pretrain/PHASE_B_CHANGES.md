# Floating-hand pretrain (stage 1) — 구현 현황

두 단계 loco-manip 계획의 1단계입니다. 떠 있는 Shadow 손 두 개로 dexterous manipulation 을
먼저 배우고, 그 결과 손목·손가락 궤적을 2단계(전신)의 추종 목표로 넘깁니다. 전제는 교수님
지적대로 "캡처의 물체 pose 는 믿을 수 있고 리타게팅된 손 pose 는 못 믿는다" 입니다.

태스크 id: `Robotis-G1-Shadow-HandPretrain-Direct-v0`

### 액션 레이아웃 (54)

손별 27, 왼손 먼저: `[pos_offset 3 | rot_offset 6D | finger 18]`

손목은 `F = K_pos * pos_offset * action_dt`, `tau = K_rot * axis_angle(R_6d) * action_dt`,
이동평균(alpha=0.2) 후 루트 바디에만 `is_global=True` 로 외력. D 항은 강체 damping(100).
리타게팅 손목에 **앵커링하지 않습니다**(사용자 결정) — 리셋만 리타게팅 pose 에서 출발합니다.

손가락은 학습 env 경로를 그대로 씁니다(레퍼런스 기준 per-step 잔차). TJ 의 절대-scale+EMA 로
갈아타지 않은 것은 "보상·관측 설계를 바꾸지 말고 몸통만 제거" 원칙 때문입니다.

### 관측 내역 (559)

```
A 자기수용감각 126 = 관절위치36 + 관절속도36 + palm자세6D12 + palm선속도6 + palm각속도6 + 손끝선속도30
B 추종         252 = 손키포인트42x3 + 델타42x3
C 물체/접촉/이력 180 = 물체pose+속도15 + 물체델타9 + 물체기준손끝오프셋30 + 관절DOF8
                     + 링크접촉마스크32 + 링크접촉력32 + 직전액션54
방향 비트        1
```
`failure_sigma=False` 라 beta 열이 없습니다. 켜면 560 으로 바꿔야 합니다.

## 구현 중 실제로 잡은 버그

단일 articulation 전제가 곳곳에 박혀 있어, 부팅만으로는 드러나지 않는 오류가 여러 개
있었습니다. 아래는 조용히 틀린 값을 내고 있었을 것들입니다.

* **link 키포인트 보상 / 접촉 일치 게이트** — 32열(양손) 인덱스를 `self.robot`(= 왼손 별칭)에
  그대로 색인. 오른손 링크가 전혀 반영되지 않았습니다. `_gather_body` 로 교체.
* **물체 declear 측정** — 왼손만 치우고 측정. 오른손이 남아 침하량을 오염시켰습니다.
* **NaN 가드** — 왼손만 검사. 오른손이 NaN 이 되어도 리셋되지 않았습니다.
* **키포인트 그룹 인덱스** — 42열 색인 `[0,21]` 을 폭 2인 `body_per` 에 적용해
  CUDA device-side assert. `[0,1]` 로 분리.
* **`Error / root_pos`** — `self.robot` 별칭 때문에 "왼손목 대 사람 골반" 거리가 찍히고
  있었습니다. 골반이 없으므로 상수 0 으로.
* **텐던 리셋 블록** — `_tendon_j{0,1}_ids` 는 한 손(22 DOF) 기준 인덱스라 36열 버퍼에
  쓸 수 없었습니다. 손별 dict 로 바꾸고 J0 는 손별 쓰기 블록에서 `_ref_j0` 로 채웁니다.
* **`export_hand_rl.py` 관절 이름 누출** — 루프 변수 `hand` 가 새어 왼손 인덱스에 오른손
  이름이 붙을 수 있었습니다. 이 파일이 이름을 저장하는 이유가 바로 그 버그 유형입니다.
* **도달성 감사의 허리 누락** — 손목이 몸통에 달려 있어 `waist_{yaw,roll,pitch}` 를 고정하지
  않으면 도달 가능한 궤적이 92% 불가로 나왔습니다. IK 재시작으로는 안 고쳐졌고(92.2 -> 87.7%),
  그게 원인 판별의 단서였습니다 — 씨앗 문제는 복구되지만 잘못된 기구학 연쇄는 복구되지 않습니다.

## TJ 구현에서 발견한 결함 (우리 쪽에서 보정)

`rotation_6d_to_matrix` 는 **0 근방에서 퇴화·불연속**입니다 (pytorch3d 0.7.9 실측):

```
[0,0,0,0,0,0]          -> det=0 (회전행렬이 아님)
[1e-6]*6               -> det=0, 축각 0.676 rad
a[0]=+1e-5 -> 0.0000 rad  /  a[0]=-1e-5 -> 2.2214 rad
```

마지막 줄이 문제입니다: 성분 하나의 부호가 뒤집히는 것만으로 토크 지령이
`2.2214 * 160 / 30 = 11.8 N*m` 튑니다. 정책의 **평균** 액션은 0 에서 출발하고,
`export_hand_rl.py` 의 결정론적 롤아웃은 바로 그 평균을 쓰므로 2단계가 받을 궤적이
이 불연속점 위에서 만들어질 수 있습니다.

`wrist_rot6d_identity=True`(기본)로 변환 전에 항등 6D `[1,0,0,0,1,0]` 을 더합니다.
액션 0 -> 정확히 항등회전 -> 토크 0, 0 근방 `det=1`. 되돌리기: `False`(TJ 원문).

## 상태 캐시 (손 전용 176 레이아웃)

부모 캐시는 222 = 보상1 + 루트13 + 물체13 + jpos65 + jvel65 + smoothed65 이고 "루트 하나 +
관절 65열" 전제가 슬라이스 오프셋에 박혀 있습니다. 손 전용은 루트가 둘(손목)이고 구동 관절이
36열이라 176 으로 다시 잡았습니다.

```
[0]        reward (순위 키)
[1:8]      왼손목 pose (env-local pos 3 + quat wxyz 4)   [8:14]   왼손목 속도 (선3+각3)
[14:21]    오른손목 pose                                  [21:27]  오른손목 속도
[27:34]    물체 pose                                      [34:40]  물체 속도
[40:76]    구동 관절 위치 36 (왼 18 -> 오른 18)             [76:112] 구동 관절 속도 36
[112:120]  텐던 축 J0 위치 8 (왼 4 -> 오른 4)               [120:128] 텐던 축 J0 속도 8
[128:164]  smoothed_actions 36
[164:170]  손목 힘 EMA (손별 3)                            [170:176] 손목 토크 EMA (손별 3)
```

부모에 없던 두 블록을 넣었습니다.

* **텐던 축 J0 8칸** — 구동 36열에 J0 가 없습니다. 캐시 히트에서도 J0 를 레퍼런스에서
  재구성하면 캐시된 J1 과 *다른 프레임의* J0 가 짝지어져 텐던 제약이 깨집니다. 캐시의 목적은
  실제로 방문한 상태를 그대로 되살리는 것이므로 J0 도 담습니다. 레퍼런스 경로는 그대로
  `min(_ref_j0, J1)` 을 씁니다 (`_use_ref_j0` 마스크로 경로별 분기).
* **손목 힘/토크 EMA 12칸** — 손목 임피던스 컨트롤러의 적분 상태입니다. 0 으로 리셋하면 손을
  들고 있던 힘이 사라져 복원 직후 손이 처집니다 (무액션 침강 실측 0.038 m/s).

속도 부호 반전 대상(`_CACHE_VEL_SLICES`)은 손목 속도 6x2, 물체 속도 6, 구동 관절 속도 36,
J0 속도 8. **손목 힘/토크 EMA 는 반전하지 않습니다** — 속도가 아니라 컨트롤러 상태이고,
시간을 거꾸로 돌려도 중력은 그대로여서 손을 들고 있던 힘은 계속 들고 있어야 합니다.

### 발산 상태 차단 (부모에 없던 게이트)

떠 있는 손은 수치적으로 터질 수 있습니다 — 캐시를 끈 순수 물리에서 무작위 액션 0.5 배율 +
종료 비활성으로 400스텝 굴렸을 때 **200스텝에서 관절값이 2.03e16** 에 도달했습니다. 종료
게이트가 켜져 있으면 그 전에 리셋되지만, 캐시는 스텝마다 쓰고 프레임당 최고 보상 1행만
남기므로 **한 번의 오염이 영구적**입니다. 그래서 품질 게이트(손끝/물체)와 별도로 유한성과
크기를 직접 검사하고, 거부율을 `Diag / cache_reject_frac` 로 노출합니다 (정상 = 0).

캐시의 효과를 **확인하지도 반박하지도 못합니다**. 이 env 에서 캐시의 한계효용이 작을 수 있는
구조적 이유도 있습니다 — `_ref_joints` 가 있으면 RSI 후보가 처음부터 전 프레임이라
"복원 가능한 프레임" 이 이미 100% 여서, 전신 학습에서 캐시가 해결했던 냉시작 문제(넘어짐 때문에
프레임 0 근처에 갇히는 것)가 여기서는 발생하지 않습니다. 캐시가 주는 것은 커버리지가 아니라
**출발 상태의 물리적 정합성**(레퍼런스 자세는 물체를 관통한 채로 출발할 수 있음)이므로,
본 학습 규모에서 `Diag / death_frac` 과 `Error / fingertip` 로 판단하는 것이 맞습니다.

## 벤치마크 스크립트

`scripts/benchmark/parahome/train_sequences_hand_pretrain.sh` — 클립당 7단계:

1. SMPL-X 클립 확인 → 2. 손 접촉맵 → 3. PyRoki 리타게팅(env_pyroki) →
4. **손목 FK 사이드카**(`export_wrist_ref.py`) → 5. 학습 → 6. **결정론적 롤아웃 내보내기**
(`export_hand_rl.py` → `hand_rl.npz`, stage 2 목표) → 7. **도달성 감사**(보고 전용)

sonic_residual 스크립트와의 차이: SONIC 준비 단계 없음(`use_sonic=False`), 대신 `wrist_ref.npz`
가 **필수**(env 가 없으면 FileNotFoundError), 그리고 학습 후 내보내기·감사 단계가 추가됩니다.
클립 목록은 sonic_residual 과 **같은 13개**로 맞췄습니다 — stage 1 산출물이 stage 2 입력이라
두 단계가 다른 집합을 덮으면 비교가 성립하지 않습니다.

환경변수: `FORCE=1`, `SKIP_RETARGET=1`, `SKIP_EXPORT=1`, `SKIP_AUDIT=1`, `CLIP_CLASS`,
`CLIPS_OVERRIDE`, `NUM_ENVS`, `TIMESTEPS`, `VIDEO`.

### 스모크 실행에서 잡은 것들

* **`find_ckpt` 의 `xargs ls -t`** — `find` 가 아무것도 못 찾으면 xargs 가 인자 없이 `ls -t` 를
  실행해 **현재 디렉터리**를 나열하고 그 첫 항목(측정값: `wandb`)을 반환합니다. 호출부의
  `[[ -z ]]` 검사가 이걸 못 잡아 `cp wandb agent.pt` 로 넘어갑니다. 학습이 첫
  `checkpoint_interval`(2000 스텝) 전에 끝나면 매번 발생합니다. 이 스크립트는 `xargs -r` +
  `[[ -f ]]` 로 막았습니다. **같은 함수를 쓰는 나머지 9개 벤치마크 스크립트에는 그대로
  남아 있습니다** (hocap 4, oakink 2, parahome 3) — 필요하면 함께 고쳐야 합니다.
* **`export_hand_rl.py` 가 한 번도 실행된 적이 없어 4곳이 깨져 있었습니다**:
  `Runner` 에 파싱된 cfg 대신 entry-point 문자열을 넘김 / `SkrlVecEnvWrapper` 누락 /
  `act()` 시그니처(`states` 필수 위치인자) / `set_running_mode` 는 skrl 2.1 에 없음
  (`enable_training_mode`).
* **프레임 레이트 불일치** — `hand_rl.npz` 는 control_fps(50 Hz, 501 프레임), 사이드카는
  소스 30 Hz(301). `min()` 으로 자르면 시간축이 어긋납니다(실측: 프레임 100 에서 13 cm).
  meta 에 `fps` 를 넣고 감사에서 인덱스 매핑으로 정렬했습니다.
* **감사가 IK 실패를 거대한 거리로 위장** — `best` 초기값이 `(1e9, 1e9)` 였고 NaN 비교는 항상
  False 라 갱신이 안 되면 센티넬이 그대로 나와 `p90 = 1e12 mm` 로 인쇄됐습니다. NaN 으로
  바꾸고 "풀이실패" 열로 따로 셉니다 — 도달 불가와 다른 사건입니다.
* **내보내기에 발산 가드 추가** — 롤아웃은 `termination=False` 로 돌아서 발산한 env 를 리셋하는
  게이트가 없습니다. 실측: 손목 위치 1.85e15 m, 손가락 5.79e19 rad 가 그대로
  `hand_rl.npz` 에 기록됐습니다(비정상 프레임 77/501, 첫 프레임 140). 이제 프레임별로
  유한성·크기를 검사하고 하나라도 걸리면 **쓰지 않습니다** — stage 2 가 조용히 소비하는
  오염된 파일이 파일 없는 것보다 나쁩니다.

### `wrist_action_dt` 정정 (사용자 지적)

`1/30` 하드코딩 → **제어 주기에서 유도**(`sim.dt x decimation` = 1/50). TJ 의 cfg 자체가
`action_dt = 1 / action_fps` 로 정의하므로, 우리 루프가 50 Hz 인 이상 `1/50` 이 **충실한
이식**이고 `1/30` 이 이탈이었습니다.

효과는 게인 조정이 아니라 **안정성 수정**이었습니다. 같은 체크포인트로 같은 롤아웃을 돌렸을 때:

| action_dt | 왼손목 \|위치\|max | 왼손 \|q\|max | 결과 |
|---|---|---|---|
| 1/30 (133.3 N, 중력의 14.9배) | 1.85e15 m | 5.79e19 rad | 발산 |
| 1/50 (80.0 N, 중력의 8.9배) | 1.01 m | 1.62 rad | 정상 |

손 질량은 0.911 kg(24 링크, `shadow_float_l.usd` 실측) = 중력 8.94 N 입니다. 133 N 은 PhysX 를
터뜨릴 만큼 과했습니다.

세 번째 해석도 있습니다: TJ 의 제어 스텝당 **변위**(v = F/damping)를 보존하려면 50 Hz 에서
`action_dt = 1/18` 이 필요합니다(TJ 0.0444 m/단위/스텝 → 1/50 에서 0.0160 m). TJ cfg 가
그 기호를 "제어 주기" 로 정의하므로 문자 그대로의 해석을 택했고, cfg 주석에 세 해석을 모두
남겨뒀습니다.

* **동역학 불일치** — 떠 있는 손목에는 팔의 관성이 없습니다. `K_pos` 스프링 + damping 100 이

  것으로 예상합니다.
* **액션 0 에서의 침강** — 무액션 20스텝(0.4s)에 손목이 17 mm 내려갑니다(속도 0.038 m/s).

  학습 초기에 손이 바닥으로 흐르는 구간이 있을 수 있습니다.
* **무작위 정책에서 물체 회전 종료가 지배적** — 200스텝 중 184회 종료가 전부
  `Term / obj_rot` 입니다(`Error / obj_rot` 0.41 rad). 손목 힘이 최대 133 N 이라 무작위
  액션이 물체를 즉시 돌립니다. 무액션에서는 종료 0 이므로 게이트 자체 문제는 아니지만,
